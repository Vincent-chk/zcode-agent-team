## 2. 快速开始

```bash
npm ci                       # 必须用锁文件（registry.npmmirror.com）
npm run build                # runtime/（daemon/hooks/team-ctl/panel/companion）
npm run check                # typecheck + plugins validate + daemon 冒烟
x
npm run test:cov             # 覆盖率门槛
```

期望：`npm run check` 末行 `SMOKE PASSED`；`npm test` 末行 `Tests 899 passed (899)`（fileParallelism=false）。

0.5.2 验收分两口径记录（2026-11-02）：①**日常口径** `npm test`（不带插桩）**75 文件 / 899 用例全部通过**，227.2s；②**覆盖率口径**（`npx vitest run --coverage --exclude test/coord/integration/f32.test.ts`）**74 文件 / 898 用例通过**，聚合覆盖率 statements **91.65%**、branches **85.24%**、functions **92.65%**、lines **93.47%**，四项门槛全过。`f32.test.ts` 为性能基准（自带 2000ms/200ms 阈值），在覆盖率插桩 + 全量并行下会因 CPU 争用偶发超时（见 §8 flaky ③），单跑 903ms/41ms 达标——故覆盖率口径以排除它 + 单跑复核的方式记录。文本审计 **26** 项、S9 **12** 检查、`npm run check`（typecheck + validate + SMOKE）全过。另 `test/provider/session-isolation.test.ts` 曾在全量+插桩下出现 2 例负载抖动（单跑 38/38 全绿），同属环境压力。

## 3. 各脚本详解

### 3.1 `scripts/smoke-daemon.mjs`
- 用途：不经宿主直接拉起 daemon，验证 MCP 握手、9 工具列表、`ui://` 与 `team://view` 资源（0.4.0：`team://models` 已下线）、`team://view` 订阅与推帧、面板回环、心跳、SIGINT 优雅处置、非法配置 fail-loud。
- 前置：`npm run build`。
- 期望：全部 `OK` + `SMOKE PASSED`；配置错误场景打印 `TEAM_INVALID_CONFIG` 但继续可读诊断。

### 3.2 `scripts/e2e/run.mjs`
```bash
node scripts/e2e/run.mjs                    # 全跑
node scripts/e2e/run.mjs --only s1,s3       # 指定剧本
node scripts/e2e/run.mjs --retries 1        # 失败重试
```
- 剧本：S1 协作（真模型）、S2 fork（真模型）、S3 崩溃矩阵（确定性）、S4 限额（真模型）、S5 并发（fake-zcode）、S6 hook 通道（真模型）、S7 编排旅程（真模型，显式 always，D26/D28）、S8 auto 默认链冒烟（真模型，D28：简单任务不建队+注入无模式段）、S9 订阅降级自干（确定性：直跑 `runtime/team-hooks.mjs` + `createProbeDb` 三源夹具；14 检查 = 数据隔离 / startup `model` 载荷注入+锚 / 去重 / 第三方不注 / 首轮 UPS「仅选模条目」形态 / 快照第三方不注 / 源1 正例 / 源3 正反例 / off / 空库乐观 / 锚在零输出 / hint 误报撤回恰一次 / resume 切第三方撤回）。
- 真实订阅 db 手工复验（套餐面仅交互会话可达，自动化不可覆盖）：`echo '{"hook_event_name":"SessionStart","session_id":"<真实订阅会话 id>","source":"startup","cwd":"/tmp","model":"account:bigmodel-individual-coding-plan/GLM-5.3"}' | TEAM_PLUGIN_DATA=$(mktemp -d) ZCODE_SESSION_ID=<同 id> node runtime/team-hooks.mjs`，stdout 应含 `informational, not a restriction`；去掉 `model` 字段改用真实 db（默认路径只读）则验证三源路径。
- **降级提示措辞红线（2026-11-02 真会话教训）**：注入文本必须是**事实描述 + 恢复条件**，绝不能用禁止性祈使句（`do not call spawn_teammate` 等）。原因：SessionStart 注入进入对话历史后不可撤销，模型会长期服从该禁令；此后即便切到第三方模型、撤回提示也已注入，模型仍拒绝尝试 spawn——用户看到的现象就是「切成第三方还是不能用」。`scripts/text-audit.mjs` 已加反向断言（`do not call` / `must not` / `never call` 一律不得出现）。
- **判定必须看用户可见结果**：验证降级/恢复类功能时，内部锚（`soloNotifiedAt`/`soloRetractedAt`）只证明「提示注入过」，**不等于**「用户能用了」。U 类旅程的判定标准是：切模型后实际 `spawn_teammate` 成功（成员出现）或模型明确表示会调用；只看锚落盘会把上述事故误判为 PASS。
- 环境变量：`ZCODE_BIN`、`TEAM_DATA_ROOT`、`TEAM_DB_PATH`、`E2E_OUT`、`E2E_WS`、`E2E_MODEL`；`E2E_FAKE=1` 走确定性 fake-zcode。
- 隔离：每个剧本独立数据根/DB 子进程，结果写 `result.json`，任一失败非零退出。

### 3.3 `scripts/crash-matrix.mjs`
```bash
node scripts/crash-matrix.mjs --out /tmp/crash.json
```
- C1 kill teammate 轮次；C2 kill 协调者（接任 ≤5.5s）；C3 kill 代理 daemon；C4 模拟宿主回收 SIGINT→260ms→SIGKILL（轮次存活 + 接任）；C5 写盘 burst 中 kill -9（重放干净或显式 fail-closed，`delivered ⊆ messages`）。
- 期望：每类 `verdict:"pass"`，末行 `summary.pass=true`。

### 3.4 `scripts/perf-baseline.mjs`
- 7 指标：spawn 冷启动、投递延迟（空闲/运行中）、wait 唤醒、面板渲染（8 成员 + 20 任务）、协调者 RSS、1 万行重放、daemon 冷启动可服务。
- 确定性（fake-zcode）；超门槛非零退出。

### 3.5 `scripts/security-audit.mjs`
- ①目录 0700/文件 0600/socket 0600；②数据目录外零写入（workspace 与哨兵 mtime 不变、真实 db 未触碰）；③源码静态审计 db 只读打开点；④伴生面板仅回环 + token（无/错 token 403，正确 200）。

### 3.6 `scripts/upgrade-drill.mjs`
- 旧团队数据可读；删除 checkpoint 后冷启动重建；进行中剧本 SIGKILL 后新实例纳管续跑；记录 Node/版本指纹。对应 SF11。

### 3.7 `scripts/text-audit.mjs`
- esbuild 现场打包 `src` 文本常量后断言（不复制文本）：策略全文与插值、身份两分支、无 id 框架头、27 错误码模板、UI 词典 25 键 zh/en 键集一致、默认无探针。

### 3.8 `scripts/visual-regress.mjs`
```bash
node scripts/visual-regress.mjs                 # 断言 + 与基线比对
node scripts/visual-regress.mjs --update        # 重录基线（仅在 UI 变更且评审通过后）
node scripts/visual-regress.mjs --only=full,failure
```
- 8 夹具 × 浅/深 × zh/en × 面板/卡片 = 64 张 + detail 3 组（单轮摘要/两轮摘要/空态）× 浅深 × zh/en = 12 张，共 **76 张**基线（0.4.0：settings 弹窗 4 张随功能下线注销）；几何断言 ±1px、V12 硬编码色扫描、V15 像素自比对 ≤0.5%。
- 〔视图修订 2026-10-25·二次〕detail 断言按 fixture 分支：`detail`（单轮摘要：msgCount 3 / badge 1 / toolGroup 1）、`detail-summary`（两轮摘要：msgCount 6 / badge 1 / toolGroup 2）、`detail-empty`（空态）；通用断言含**无模式切换按钮**（`modeButtonCount=0`）、只读（无发送控件）、占满内容区、横向溢出 ≤1px。
- 〔0.4.0 收敛〕成员配置入口全下线：断言改为**反向零存在**——全部页面 `gearCount=0`（`[data-member-gear]`/`.member-card`/`[data-settings-overlay]` 计数）+ **全页面零凭据输入**（`input[type=password]`、`name*=apiKey|baseURL`、`textarea` 计数均为 0）。
- 基线目录：`test/visual/baseline/`（入库，勿手改 PNG）。

### 3.9 `scripts/f10-companion.mjs`
- Playwright 驱动 `runtime/ui/team-companion.html`：hover 150±20ms、离开 120±20ms、pin、Escape 焦点归还、外点关闭、锚定 top+5、紧凑模式；页面数据用内嵌 mock，与数据源解耦。

### 3.10 `scripts/stage4-real.mjs`
- 真实模型 S0–S10 伙伴运行时验收（参数见文件头）；成本较高，发布前跑一次。

## 5. 夹具与数据隔离

- vitest 统一 `fileParallelism: false`（真实子进程与时序断言）；`testTimeout 15s`。
- 测试数据写 `os.tmpdir()` 或 `TEAM_DATA_ROOT` 指定目录；**不要指向真实 `$ZCODE_PLUGIN_DATA`**。
- 会话库夹具：`createTestSessionDb`（`scripts/e2e/common.mjs`）建最小 schema 的临时 sqlite；真实 db 仅只读。
- exFAT（外置卷）会生成 `._*`：测试/视觉/打包均需过滤（vitest exclude、readdir 过滤、release 打包时排除）。

## 7. 已知环境限制

| 限制 | 影响 | 规避 |
|---|---|---|
| 真实模型剧本需要登录态与网络 | S1/S2/S4/S6/S7/S8 失败可能是环境而非代码 | 先跑 `E2E_FAKE=1` 的确定性链路，再跑真模型 |
| Playwright 需 chromium（`~/Library/Caches/ms-playwright`） | 视觉/伴生矩阵无法启动 | 安装 chromium 或用 `PLAYWRIGHT_BROWSERS_PATH` 指向已有缓存 |
| 屏幕锁定 | 桌面 UI 实拍/交互不可用 | 解锁后再执行；CI/headless 用夹具与 Playwright |
| 外置 exFAT 卷 | `._*` 噪声、git pack 索引告警 | 过滤与打包排除；`find .git -name '._*' -delete` |
| 外置 exFAT 卷 · 原生二进制（2026-11-02 实测） | 卷上原生 Mach-O（esbuild bin、rolldown/lightningcss/fsevents 的 .node）触发 CODESIGNING Invalid Page → 进程被 SIGKILL（tsc/esbuild/vitest 秒杀无输出）；npm 本地缓存可能投毒损坏包 | `npm cache clean --force` 后 `npm ci --ignore-scripts`；把原生二进制**原样解压到 APFS**（如 `~/at-native/`）再软链回 `node_modules` 对应路径（esbuild bin + 三个 .node）；每次 `npm ci` 后需重做软链 |
| 外置 exFAT 卷 · 构建产物撕裂（2026-11-02 实测） | `npm run build` 写大 bundle（team-daemon.mjs ~1MB）偶发落盘撕裂 → daemon 起不来（wire 测试 10s 超时 / smoke 挂 unsettled await） | 〔D31 已自动化〕build.mjs 产物写完后对 7 个产物 `node --check`，坏则整体重建 ≤3 次（仍坏 exit 1 = 卷异常）；release.mjs 对 staging/解包树再校验。手工复核：`node scripts/check-bundles.mjs` |
| 在 teammate 会话内跑全量测试 | 当前进程继承 `TEAM_LEAD_MODE`/`TEAM_SPAWN_IDENTITY`/`TEAM_PROJECT_DIR`/`TEAM_PLUGIN_*` 等变量，hook/策略注入类用例会读到本会话上下文而失败（stage-8 实测 9 例） | 先净化再跑：`env -u TEAM_LEAD_MODE -u TEAM_SPAWN_IDENTITY -u TEAM_PROJECT_DIR -u TEAM_PLUGIN_DATA -u TEAM_PLUGIN_ROOT npx vitest run` |
