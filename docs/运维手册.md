# 运维手册（Agent Teams，0.1.2）

> 面向维护者：数据目录、日志、锁与接任、清理、db.sqlite 只读依赖、常见故障处置。
> 结构背景见 `docs/架构说明-as-built.md`；用户向说明见 `README.md`。

## 1. 数据目录与权限

`$ZCODE_PLUGIN_DATA`（安装时由宿主注入，典型值 `~/.zcode/cli/plugins/data/agent-team@<market>`）：

```text
logs/         hooks.jsonl / daemon-lifecycle.jsonl / provider.jsonl /
              requests.jsonl / meta-log.jsonl / signals.jsonl / panel-http.json
meta/         runtime-config.json（hook 读的配置兜底）+ 最近工具调用入参/结果快照
session-map/  会话 → 团队/成员映射（hook 与 daemon 双写共享注册表）
session-map.json
teams/<sessionId>/
  events.jsonl           追加日志（唯一真源）
  checkpoint.json        重放加速
  coordinator.lock       当前协调者（owner）
  coordinator.lock.hb-*  心跳
  coordinator.sock       RPC（linux/macOS unix socket）
  rpc.token              RPC token
  coordinator.audit.jsonl
  lead/state.json
  members/<memberId>/origin.json, run/turn-*.json, run/turn-*.out, receipts.jsonl
  ui/view-snapshot.json
```

权限纪律（SF12 审计）：目录 0700、文件 0600、socket/token 0600；数据目录外零写入（workspace 不变、宿主 `db.sqlite` 只读）。

## 2. 日志速查

| 文件 | 关键字段 | 用途 |
|---|---|---|
| `logs/hooks.jsonl` | `ts` `event` `input_session_id` `env_overlay` `cwd` | 判断 hook 是否运行、注入时看到的插件路径/数据目录/配置 env |
| `logs/daemon-lifecycle.jsonl` | `event`(startup/dispose-ok/exit) `pid` `node` `nodeWarn` `cwd` `teamEnv` | daemon 拉起/回收、Node 自检、数据目录 |
| `logs/provider.jsonl` | 轮次孵化/退出/投递 | teammate 轮次与消息投递细节 |
| `logs/requests.jsonl`、`logs/meta-log.jsonl` | 工具名/耗时/入参结果引用 | 工具面与面板回环排障 |
| `logs/signals.jsonl` | 信号与处置 | 崩溃/回收分析 |
| `teams/<id>/events.jsonl` | `{seq,ts,writer,event}` | 团队唯一真源；`team-ctl tail` 跟随 |
| `teams/<id>/coordinator.audit.jsonl` | 获取/释放/抢占 | 接任与锁竞争取证 |

日志只追加，不自动轮转。长期运行按需归档：`mv logs/*.jsonl <backup>/`（daemon 会重建文件；不要删 `teams/`）。

## 3. 锁与协调者接任

- 锁模型：owner 文件 O_EXCL 创建后**永不改写**；心跳文件按 token 分文件续期；`observe` 读 owner+心跳；`steal` 先 guard 再复核 token/inode/过期，误抢会回滚。
- 参数（`src/coord/lock.ts` 的 `DEFAULT_LOCK_TUNING`）：心跳 1000ms，过期 4500ms，轮询 200ms。实测 kill -9 后接任 ≤5s（F29/F32、崩溃矩阵 C2）。
- 缺位窗口：客户端收到 `TEAM_DISPOSED`（消息 `Agent Teams coordinator is unavailable (between coordinators); retry the request shortly`）属临时错误，退避重试即可（D8）。
- 排查：
  ```bash
  node dist/team-ctl.mjs state <teamDir> --json     # writers 字段显示当前写者
  cat <teamDir>/coordinator.lock                    # pid/bootId/token/acquiredAt
  ls <teamDir>/coordinator.lock.hb-*                # 心跳文件
  tail <teamDir>/coordinator.audit.jsonl            # 接任历史
  ```
- 处置：**不要手删活锁**。若确认协调者已死且心跳过期，下一个 daemon 会自动接任；必要时重启任务（新 daemon 冷启动即重放）。
- 生命周期：daemon 空闲 30s 被宿主回收是**常态**；回收 SIGINT→SIGTERM 仅约 260ms，处置只轻量落盘（D9），孤儿轮次由冷启动 `adoptOrphans` 定案/纳管（D17）。

## 4. 数据目录清理

原则：**先备份，再删除**；`events.jsonl` 是唯一真源，手工编辑会破坏 seq 连续性导致 fail-closed。

```bash
DATA="$HOME/.zcode/cli/plugins/data/agent-team@<market>"
du -sh "$DATA"
tar -czf ~/agent-team-backup-$(date +%Y%m%d-%H%M).tar.gz -C "$(dirname "$DATA")" "$(basename "$DATA")"
```

| 目标 | 做法 |
|---|---|
| 清空全部团队数据 | 删除整个 `$ZCODE_PLUGIN_DATA`（等价默认卸载的数据处置） |
| 只清某个团队 | 停止该任务窗口 → 删除 `teams/<sessionId>/` |
| 只清日志 | 归档/删除 `logs/*.jsonl`（保留 `teams/`） |
| 清工具入参快照 | 删除 `meta/<tool>-*.json`（保留 `meta/runtime-config.json`） |
| 卸载但保留数据 | CLI：`zcode plugins uninstall agent-team@<market> --keep-data --force` |
| 卸载且删数据 | CLI 默认卸载；桌面 UI 卸载（确认框会明示删除） |

卸载后注意：仍打开的相关任务窗口会重建**空**数据骨架（`events.jsonl` 0 字节），原数据不会恢复；清理后请关闭相关任务窗口或重启宿主。

## 5. db.sqlite 只读依赖

- 路径：`~/.zcode/cli/db/db.sqlite`（可用 `TEAM_DB_PATH` 覆盖，测试/演练用）；`node:sqlite` 以 **readonly** 打开（`src/provider/transcript.ts`、`src/provider/session-breeder.ts`）。
- 用途：①transcript/detail 回填成员会话内容（按 `session_id` 索引查询）；②会话培育时读取 anchor/子会话元数据。
- 约束：**绝不写该库**（D25 白名单仅 tasks-index 的两个写入点）。宿主升级可能改 schema；查询失败只降级会话内容，不影响团队域。
- 性能纪律：message/part 必须走 `session_id` 索引；禁止对 part 全表 LIKE（1.6GB 扫描 10s+）。首条 `real_user` 文本落库约 +3s，轮次结束才出 `--json` 输出。
- 排障：
  ```bash
  sqlite3 ~/.zcode/cli/db/db.sqlite "select count(*) from message where session_id='<sess>';"
  node dist/team-ctl.mjs transcript <teamDir> <member> --limit 20
  ```

## 6. 环境变量（运维/排障）

| 变量 | 默认 | 说明 |
|---|---|---|
| `TEAM_PLUGIN_DATA` | 宿主注入 | 数据目录（hook 与 daemon 同源） |
| `TEAM_ZCODE_BIN` | 自动发现 | teammate 轮次使用的 zcode 入口 |
| `TEAM_DRAIN_ON_DISPOSE` | `keep` | `kill` 启用完整处置序列（SIGTERM→SIGKILL） |
| `TEAM_DB_PATH` | `~/.zcode/cli/db/db.sqlite` | 会话库只读探针路径 |
| `TEAM_TASKS_INDEX` | `~/.zcode/v2/tasks-index.sqlite` | 任务索引（仅白名单写入） |
| `TEAM_COMPANION` | 关 | `1` 启动伴生面板 HTTP（127.0.0.1 + token，注册 `logs/panel-http.json`） |
| `TEAM_DEBUG_TOOLS` | 关 | `1` 暴露 `team_ping` 诊断工具 |
| `TEAM_DEBUG_DELIVERY` | 关 | `1` 记录 pending 补投/延后原因 |
| `TEAM_WAKE_LEAD` | 关 | `1` 空闲 Lead 唤醒灰度；`TEAM_WAKE_LEAD_MIN_IDLE_MS` 默认 30000 |
| `TEAM_SESSION_ISOLATION` | `child` | `legacy` 回滚到旧顶层会话（会出现在任务栏） |
| `TEAM_FORK_MAX_CHARS` | 24000 | fork 兜底转录截断预算 |
| `TEAM_POLICY_PROBE` | 关 | 仅 F08 取证用策略探针 |

## 7. 常见故障处置

| 现象 | 定位 | 处置 |
|---|---|---|
| hook 不触发 | `plugins list` 状态；`logs/hooks.jsonl` 无新行；设置→钩子 | 确认启用、新开会话、检查插件 diagnostics；升级后旧会话仍用旧版本 |
| `Duplicate plugin hooks file ignored` | 安装期 warning | 已知项 D-1：manifest hooks 与宿主自动发现重复，宿主忽略；hook 实测正常；计划 0.1.3 清理清单 |
| 成员卡在 provisioning | `logs/provider.jsonl`、`provider` 错误 | 检查 `TEAM_ZCODE_BIN`、名额、磁盘；冷启动对账会把不可达 provisioning 定案 |
| 消息不送达 | `team-ctl state` mailbox、`logs/provider.jsonl`、`TEAM_DEBUG_DELIVERY=1` | 目标运行中=queued（边界交付，D2）；空闲应拉起；检查 receipts |
| 面板不刷新 | 面板心跳日志、`ui/view-snapshot.json` | 关闭重开任务；`team-ctl state` 交叉验证；面板连接失联会自动重建 |
| 协调者反复交替 | `coordinator.audit.jsonl`、锁心跳 | 检查是否存在多副本（inline + 市场安装并存）；保留一个安装 |
| 重放失败 `persisted … invalid` | `events.jsonl` 尾部/seq | 备份目录后从 checkpoint 或全量重放恢复；不要手工修补行 |
| 任务栏出现成员会话 | tasks-index | `team-ctl sidebar-audit <teamDir>` 先 dry-run，再 `--apply`（幂等，只归档并写台账） |
| Node 版本过低 | `logs/daemon-lifecycle.jsonl` 的 `nodeWarn` | 升级到 Node ≥22 |

## 8. 例行巡检（建议）

1. `zcode plugins list --json`：版本、rootPath、diagnostics 无 error；
2. 每个活跃团队 `team-ctl state --json`：`writers` 数量 ≤1、无 `failure`；
3. `logs/daemon-lifecycle.jsonl`：`nodeWarn` 全为 null；
4. 磁盘：`du -sh $ZCODE_PLUGIN_DATA`（`meta/` 增长最快，可按需清理）；
5. 安装唯一性：`plugins list` 中不应同时出现 `agent-team@inline` 与市场安装副本。
